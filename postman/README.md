# Testing the API with Postman

This folder lets you test every Komute-Local endpoint in Postman, or from the command line with Newman. All the sample data here is fake. Never put real licence photos in this folder.

| File | What it is |
|---|---|
| `Komute-Local.postman_collection.json` | 33 requests in 7 folders, each with automatic tests |
| `Komute-Local.postman_environment.json` | The environment: `baseUrl`, `apiKey`, `authEnabled` (authentication off) |
| `Komute-Local-auth-on.postman_environment.json` | Authentication on with the shared local TEST key. Start the node with `.\run.ps1 -ApiKey komute-local-TEST-key-not-for-production`. Never use this key in production |
| `samples/licence_back_fake.png` | The back of a fake Ontario licence with a real AAMVA PDF417 barcode |
| `samples/no_face.png` | A plain image with no face. Used as the selfie and licence front, and as an unreadable barcode |
| `samples/vehicle.png` | A synthetic car photo |

The collection is generated by `scripts/make_postman_collection.py`. Change that script and run it again rather than editing the JSON by hand.

## 1. Start the node

In PowerShell, from the repository folder:

```powershell
.\run.ps1 -NoBrowser
```

Wait for `Uvicorn running on http://127.0.0.1:8000`. Authentication is off. `run.ps1` also sets `KOMUTE_RESPONSE_BARCODE_FIELDS=true`, so responses include every decoded barcode field.

## 2. Import into Postman

1. Open Postman. Select **Import** (top left).
2. Drag in both JSON files from this folder. Select **Import**.
3. In the top-right environment menu, choose **Komute Local**.
4. Set the working directory, so Postman can find the sample images:
   **Settings** (gear icon) → **General** → **Working directory** → **Choose**. Pick this `postman` folder, for example `C:\Users\<you>\OneDrive\Desktop\Komute-Local\postman`.
   If Postman says a file is "not in your working directory", this step was skipped.

## 3. Run the tests

- **One request:** open it and select **Send**. The **Test Results** tab shows each check.
- **Everything:** right-click the **Komute-Local API** collection → **Run collection** → **Run Komute-Local API**. Keep the folder order: folder 3 uses the `request_id` that folder 2 saves.

Expected result with authentication off: 33 requests, 0 failures. One run takes about 10 seconds.

## 4. What each folder checks

| Folder | Requests | What it proves |
|---|---|---|
| 1. Health and monitoring | `GET /health`, `GET /v1/system` (JSON and browser), `GET /` | The node is ready, the models are loaded, memory is under the limit, and no secret is returned |
| 2. Verify: main flow | `POST /v1/verify` with the fake licence | Stage 1 passes all 7 cross-checks. The selfie has no face, so the decision is `REJECTED` with the retryable `FACE_NOT_FOUND_SELFIE`. The audit manifest is signed |
| 3. Idempotency | Replay with the same data, replay with changed data, `GET /v1/sessions/{id}`, unknown id | The same request returns the stored result. Changed data returns `409`. A stored session can be read back. An unknown id returns `404` |
| 4. Stage 1 cross-checks | Wrong class, issue date, expiry date, date of birth, licence number, province and name; the accepted variants | Each mismatch gives its final reason code and a failed row in `stages.barcode.checks`. Class case and licence hyphens are ignored. A one-letter name typo scores about 94% and passes the 90% mark |
| 5. Barcode problems | Licence back without a barcode | `BARCODE_UNREADABLE`, retryable, with the retake message. Face and vehicle do not run |
| 6. Input validation | Missing or malformed fields | `422` with `MISSING_FIELD`, `INVALID_FIELD` or `CONSENT_REQUIRED`, and never a decision |
| 7. Authentication | Wrong key, no key, verify without a key | `401` when authentication is on. With authentication off, the key is ignored |

Every response is also checked for the security headers and for an answer within 60 seconds.

## 5. Testing with authentication on

1. Stop the node (Ctrl+C), then start it with `.\run.ps1 -NoBrowser -WithApiKey`.
2. Open `%LOCALAPPDATA%\komute\dev.env` and copy the value of `KOMUTE_API_KEY`. Do not paste it into chats, tickets or commits.
3. In Postman, open the **Komute Local** environment. Paste the key into `apiKey` and set `authEnabled` to `true`. Save.
4. Run the collection again. Every request sends the key as the `X-API-Key` header, except the folder 7 requests, which deliberately send a wrong key or none.

## 6. Command line (Newman)

Node.js is required. Newman is downloaded on first use.

```bash
npx --yes newman@6 run postman/Komute-Local.postman_collection.json -e postman/Komute-Local.postman_environment.json --working-dir postman
```

With authentication on, add `--env-var authEnabled=true --env-var "apiKey=<key>"`. Newman can then hang after printing the summary, because the node answers `401` before reading the upload. The results are already final: press Ctrl+C. The Postman app is not affected.

## 7. Variables

**Collection variables** hold the fake claim. It matches the fake barcode, so change both together or the checks fail.

| Variable | Value |
|---|---|
| `fullName`, `dateOfBirth`, `licenceNumber` | `Alex Jamie Tester`, `1990-03-15`, `T12345678901234` |
| `province`, `licenceClass`, `issueDate`, `expiryDate` | `ON`, `G`, `2023-09-14`, `2030-12-31` |
| `plateNumber`, `vehicleColour` | `ABC123`, `Grey` |
| `driverId`, `consentAt`, `consentPolicyVersion` | `pm-driver-1`, `2026-11-12T10:00:00Z`, `v1` |
| `rid` | A new `request_id` for every request, set by the collection pre-request script |
| `savedRid`, `savedManifest`, `savedDecision` | Saved by folder 2 for folder 3 |

The fake licence expires on 2030-12-31. After that date, expect `LICENCE_EXPIRED`. Rebuild the sample with a later `DBA` in `tests/fixtures/aamva_factory.py` and run `scripts/make_postman_collection.py`.

## 8. Testing with your own photos

Duplicate **Verify: fake licence, barcode passes**. On the **Body** tab, choose your own files for `selfie`, `licence_front`, `licence_back` and `vehicle`. Then type the matching claimed details. Keep those files outside this repository.

## Not covered here

- **`503 BUSY`:** the node runs one verification at a time. To see it, send two verifications at the same moment, for example from two Postman tabs. The second one gets `503` with a `Retry-After` header.
- **`500 ENGINE_ERROR`:** this needs an internal fault, which the unit tests simulate.
- **An `APPROVED` decision:** this needs a real face and a matching licence photo. The samples deliberately contain no real person.
